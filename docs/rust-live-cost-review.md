## 1. Exactness decisions

| Item | Verdict | Required condition |
| --- | --- | --- |
| P1 ratio rejection | **MODIFY** | Guard exceptional values; preserve the original gate, quotient and tie order; document an outward error bound. Prefer the original quotient for comb partials too. |
| P2 leakage cache | **MODIFY** | Cache the original ordered scan, including its early break; retain in-place updates and cancellation; give a numeric memory bound. |
| P3 peak-floor selection | **APPROVE** | Same neighborhood, `len/2`, and `f64::total_cmp`; scratch only. Do not apply indiscriminately to other medians. |
| P4 transform-only measurement | **APPROVE** | Share the identical buffer preparation and FFT; remove only work whose results `measure` discards. |

**P1: a rejection accelerator, never a replacement cent calculation.** `polyphony.rs` accepts when `!(abs(cents - tuning) > 45)`; `observe` uses strict `<45`/`<12`, and `current_support` strict `<35`/`<18`. Keep those inequalities literally. Fundamental bounds are centered at **+tuning**, not `-tuning`; observe/current-support have no added tuning correction. Do not wrap cents or change the rounded harmonic calculation/cast/range test.

For finite positive normal operands, a sufficient proof is: outward bounds contain every quotient the original gate accepts, with `E_gate + E_rewrite + E_bound < margin`, all errors expressed in cents. Include division/product rounding, both original logarithms and subtraction for the rewritten partial gate, and bound-generation error. Compute bounds once at the appropriate scope, round outward, and only skip strictly outside them. Survivors use the original arithmetic and accumulation order. A **0.5-cent margin** is ample relative to the observed errors, but the plan's approximate `1e-12` statement is not a portable libm accuracy guarantee; bind the bound to both pinned native and WASM implementations. An established total error bound below 0.01 cent would leave ample slack.

The proposed partial ratio `p.hz/(peak.hz*h)` is **not the same floating-point quotient** as `p.hz/(nominal*h)` followed by subtracting fundamental cents. Safer: prefilter the latter quotient against bounds centered on the already computed `cents`, then run the old partial gate. This avoids the algebraic rewrite entirely; all eight current harmonics share tolerance 12. If the builder retains the rewrite, prove its additional error bound, including rounding of `peak.hz*h`; otherwise leave this sub-optimization out.

Concrete native probe: **2,110 false rejections without padding** in 1,351,220 boundary checks; **zero with 0.5 cent**, maximum observed rewrite error `8.19e-13` cent. One original result is exactly `-12`, whereas the alternative is `-12.000000000000151`. This is evidence for padding, not exhaustive proof or a WASM result ([source](../target/live-cost-review/float_probe.rs), [output](../target/live-cost-review/float-probe.txt)).

**Exceptional values must fall back to the old expression.** Require positive finite operands/products, a positive normal quotient, and finite center/bounds before fast rejection. Negative/zero denominators, overflow/underflow, NaN and infinity must not acquire new behavior. In particular, NaN cents pass the comb's `> tolerance` rejection but fail observe's `< tolerance` filter; `!range.contains(NaN)` silently changes comb behavior. Input validation rejects nonfinite PCM, but does not prove finite interpolated peaks: the probe shows finite magnitudes `v=0.01`, `left=next_down(v)`, `right=v` with identical rounded logs, producing `0/0 → NaN` in parabolic interpolation. This is an intermediate-value counterexample, not a demonstrated PCM fixture. Do not fix it in this round.

Preserve iteration and ties: `max_by(total_cmp)` picks the **last** equal maximum, `current_support` harmonic `.find` picks the **first** match, and comb `norm > best` keeps the **first** tied fundamental. No sorting by amplitude/frequency, alternate tie breaker, or prefilter-dependent accumulation. Signed zeros/NaN payloads require bit comparisons where applicable.

**P2:** responses depend only on immutable anchor frequencies and local FFT size, so reuse is exact if expressions are unchanged. Clone the initial complex components as immutable priors; do not alias the mutable components. Keep outer pass order, anchor order and ascending original `j` order. Updates are in-place: later anchors see earlier anchors' updates within the same pass. Snapshot/Jacobi, parallel reductions, symmetric-response substitution and zero-response omission are not approved.

Finite peaks emitted in ascending FFT-bin order are frequency ordered; arbitrary supplied anchors are not. The old scan stops at the **first** `delta > 4`, even in an unsorted list. The probe's `[100,300,110]` gives no neighbor for 100 in the old scan, versus neighbor 110 in an unrestricted proximity filter. Either cache precisely the old scan or use a verified finite ordered fast path with original fallback. Find endpoints using the original rounded `(other.hz-peak.hz)/bin_hz` predicate; algebraic frequency cutoffs can disagree at ±4. Include exact endpoints and preserve self exclusion.

**P3:** `total_cmp` distinguishes signed zeros and NaN representations; equal comparator values have equal bits. Sorting and selecting the same rank therefore return identical floor bits; 44,000 random-bit-array cases passed. Clear/refill a reusable buffer to the exact original length. The full interior neighborhood has **44 entries**, not 46. Crucially, do **not** replace `voice_evidence`'s `ratios.sort_by`: its subsequent `spread` sum traverses sorted ratios, so selection changes floating accumulation order. The peak-floor neighborhood has no such downstream use.

**P4:** preserve zero padding, sample clamp/cast, mean summation/division, window multiplication, FFT plan/size/scratch and execution order exactly. `measure` reads the transformed complex buffer, not magnitudes or returned `Spectrum`. Its private analyzer's discarded magnitude state must not become an input to a later operation. Shared transform extraction is appropriate; alternative FFTs, fused arithmetic, reassociated expressions and reuse of a different window's FFT are not.

## 2. Attribution, missed wins and achievable margin

The profile supports prioritizing peak-dependent work, but its categories overlap. Short fit `77.3` + long/bass `129.2` − long compute `30.3` = **176.2 ms total fitting**; comb construction is **113.6 ms inside that total**, not extra. The remaining **62.6 ms is all non-comb fitting**, not a measured `independent` timer: it includes admission, refits, norms, allocations and result construction.

Other corrections: `measure.compute=7.3 ms` is **full compute**, not its FFT alone. P4 cannot save all 7.3 because the FFT remains. Long compute includes peak picking; it is not a pure FFT timer. Long calls are `i%4==0 || bass.is_none()`: sideband **39**, solo **54**, comp **66**, not always every fourth hop. YIN's timer also includes post-estimate evidence checks. The profile is a ten-call instrumented **mean**, not p95; scalar native/WASM ratios do not establish per-stage WASM shares. P2 removes repeated response/prior computation, not three quarters of all measurement arithmetic; observe also includes history/phase reasoning.

Additional exact candidates, in priority order if needed (measure them separately):

- **Greedy admission:** cache each immutable comb's reconstructed frequency; cache the active-parent ownership predicate per peak within a fit, independent of candidate weights/residual. Avoid repeating `powf`, harmonic/log tests across candidates. Weights change after admission, so refresh weight-dependent matching counts, positive-weight indices and norms. A cached norm can be reused across the 20 coordinate passes only while those weights stay unchanged. Preserve reduction order, signed-zero behavior and short-circuit decisions; no fewer witnesses or iterations.
- **Comb allocation:** recycle a zero-filled trial vector and swap with the best vector on strict improvement. Losing trials need not be normalized after their original full norm has established they lose. Keep the winning normalization and weighted-cents calculation exactly ordered. Do not replace dense reductions with reordered sparse reductions merely because most weights are zero.
- **Current support:** already memoized per MIDI per hop in `lib.rs`; preserve the first queried pitch/cents and uncertainty-counter update semantics. Projection/leakage loops may benefit from exact neighborhood indexing and reusable identical window coefficients, but 23 ms is the entire stage ceiling; fundamental prefilters will not eliminate sample projections. Never replace the oscillator recurrence with fresh trig, a different recurrence or FFT projections.
- **FFT/peak reuse and YIN:** 4096 Hann, 8192 Hann, 1024 local and YIN's zero-padded unwindowed transform are different operations. Cross-window reuse/sliding updates change rounding and usually evidence. Preserve long-window scheduling and tuning centers. YIN is already FFT accelerated and only about 10 ms including gates; it is not the leading opportunity.

**Exact changes alone plausibly reach 500 ms**, but 310–390 ms is an untested optimistic forecast. From 678.49 ms, the required saving is **178.49 ms (26.3%)**; at the rough 1.54 ratio that is about 116 native ms. Comb/observe plus repeated leakage work offer enough potential without changing recognition. Seek **≤450 ms p95** as engineering headroom (50 ms below the actual gate), across repeated sessions; do not declare success from a 499 ms lucky run. No candidate performance was measured in this review.

If exact work cannot pass, stop this round. A separately proposed reduction from four leakage passes to three is one possible next experiment, but changes amplitudes/phases, temporal independence and recognition; it requires a new frozen recognition decision. Peak caps likewise risk dropping quiet fundamentals and independent partial witnesses, especially in FM/dense mixtures; they are not an exact performance fix. Neither option is authorized here. Compute budget and the separate ≤1.5 s event-delay budget remain distinct.

## 3. Cancellation and memory invariants

Keep all existing cancellation checkpoints and success/error/progress ordering. New cache construction must not insert a long unchecked prepass before the first anchor check: construct each row lazily at its first-pass checked anchor, or establish an explicitly tested cancellation contract for extra checks. Preserve check-count behavior if claiming exact callback-trace equivalence. Test deterministic cancellation by callback ordinal and cancellation during maximum-peak work; no partial output publication. Faster execution need not cancel at the same wall-clock instant.

WASM currently passes `|| false`: the synchronous call is canceled by **worker termination**, not a cooperative Rust check. Preserve generation fencing, canceled-promise rejection, no late result publication and disposal/restart behavior (`ingest.worker.ts::killEngine/cancelRefinement`). Native cooperative cancellation tests do not establish browser cancellation.

The plan's “a few thousand f64” memory claim needs correction. Local measurement anchors come from the 4096 spectrum: bins 5..1109, at most **552** finite-magnitude local maxima because adjacent bins cannot both pass. The 8192 spectrum has at most **1,104**; these are structural bounds, not proposed caps. A dense local pair cache could approach **552² entries (~4.65 MiB at 16 bytes/entry)**. For finite ordered anchors, interpolation ±0.5 bin and the ±4 local-bin neighborhood give a conservative ≤34 neighbors/row, about **0.29 MiB of entries** at that layout, plus vectors/capacity/priors. Prove the actual layout/allocation bound; use the old uncached path for exceptional anchors if needed. Do not truncate neighbors to meet it.

Caches expire per measurement/fit/hop, or have bounded reusable capacity; nothing new grows with recording length. Clear stale rows when peak counts shrink. Measure allocated capacity/high-water and repeated-call retention, not just logical lengths. Preserve native 600 s and WASM 300 s limits, event/result caps, and existing JS≤96 MiB/WASM≤128 MiB budgets; browser five-cycle disposal remains required before adoption. Existing frame storage is recording-length state and must not be multiplied by per-hop caches.

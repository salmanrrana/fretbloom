## Narrow source/lifetime review

No additional product repair was justified after reviewing the root-corrected candidate. Completion adds two focused tests and the authorized generated association output. The following remains the reviewed contract, not a claim that mocks prove native drainage:

* The analysis dispatcher is synchronous. It parses a metadata fence and hands the request to one asynchronous payload helper. The reaction is the named `finishInput` function; it captures neither request, MessageEvent nor PCM. The helper and generated `analyze`/`analyzeOwned`/Asyncify call frames have returned before that reaction runs. Its completion contains metadata/result only. Active worker state is a metadata fence; there is no payload queue. Ingestion retains only the transferred, detached sender object across its await.
* Successful normal results are staged. Only the exact registered child object, engine generation, request and equal watermark release that reservation; normal completion additionally requires its staged matching result. A release alone cannot manufacture normal success. Subsequent segment copies/export wait for settlement and release.
* Cancellation rejects the user operation promptly, stamps its first 100 ms deadline and requests cooperative close. Repeat cancellation cannot renew it. Close return, result receipt, rejected RPC and terminate return are not release proof. Trap, initialization/close failure, transport errors, malformed proof and uncertain detachment conservatively refuse affected-runtime retry/export when release cannot be proved. Ordinary error/trap recovery is deliberately conservative; this run does not claim a genuine normal-error release path.
* Retained retry consumes a settled canceled attempt, joins old release and checks cancellation again before admission. It preserves canonical chunks, stopped snapshot until valid replacement, Blob/session identity and ordinary duplicate refusal. It does not reset `refineUsed` blindly. A retry canceled while queued creates no new input.
* The root dispatch guard checks the competing active owner **before assignment**. Only an explicit retry may take over a canceled route. Its finally compares attempt identity, so the old finally cannot clear the retry route. The root's two actual-dispatch red controls, green controls and extended handoff green remain unchanged at `target/retained-retry-root-fix/{red,green,green-handoff}.log`. They are dispatcher evidence, not drainage evidence.
* Exact pending-RPC result adoption and stale event refusal remain intact. The caller's explicit canceled-retry branch calls the retained operation without getPcm, restore or replacement ingestion. Explicit old-engine reanalysis retains its separate restore/allowEngineChange route. No memory pass is assigned to that route.

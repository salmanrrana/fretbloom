# Retry admission: drain application roots before replacing their owner

Source-only design, 2026-10-31. Sol6.1 xhigh; worked alone. **Recommend a small cooperative retirement protocol and two fixed admission slots, with a fail-closed fallback. No implementation or execution acceptance is claimed.** This prevents an unresolved overlap; the retained record does not demonstrate an actual product buffer-cap violation. Active source differs from this candidate. This package does not adopt either source tree.

This author owns only this new report and new `target/retry-admission-design/**`. Product, freezes and prior evidence were read-only. No tests, builds, browsers, DSP, benchmarks, WAT scans, production, database, default preview, commits or deployments ran. The other owner's minimal Firefox controls were neither used nor disturbed. No children or background work were started.

### Fixed slots and API additions

The coordinator has **one canonical slot** (an ingestion realm including any retiring predecessor) and **one copy slot** (refinement input, export, restore read, verification, or prepared WAV). It stores owner metadata, at most eight queued requests total, and one sticky failure. It never stores PCM, Blobs, closures over payloads, allocation histories, or a growing collection of dead workers. Canonical slot and copy slot refer to the same runtime where appropriate; retirement does not acquire either slot. An unresolved child belongs to its existing canonical owner. One-shot verification belongs to its copy permit. On failure reject/clear all queues and keep only a bounded quarantine record.

Proposed typed surface (declarations, not implementation):

```ts
type Owner = { ownerId: string; sessionId: string; generation: number }
type CopyKind = 'refine' | 'export' | 'restore' | 'verify' | 'wav'
type Retirement = Owner & {
  protocol: 1
  retirementId: number
  throughRequestId: number
}
type RetirementOutcome =
  | { status: 'released'; fence: Retirement }
  | { status: 'blocked'; fence: Retirement; reason: string }
// Interfaces hide constructors; a caller cannot fabricate a live permit.
interface AudioAdmission {
  canonical(owner: Owner, signal?: AbortSignal): Promise<CanonicalPermit>
  copy(owner: Owner, kind: CopyKind, signal?: AbortSignal): Promise<CopyPermit>
}
// Main-thread private permit methods seal, retire, complete, or poison a slot.
// They validate the registered Worker object and parsed retirement proof.
// A public `release()` that accepts an arbitrary ack-shaped object is forbidden.
```

Keep `createLiveRuntime(onEvent)` compatible; it imports the same document coordinator as PCM operations. Tests inject an isolated coordinator through a test factory. A newly created facade never creates/resets a production coordinator. `prepare(nextKey, options, signal?)` acquires canonical admission **before constructing ingestion**, whose `Recording` constructor already allocates a ring. The currently declared `LiveRuntime.prepare` omits the implementation's optional signal; add it. Before replacing a prepared facade, synchronously start its retirement, then await the successor's admission. Never await a new canonical permit while retaining an old owner that has not begun retirement.

Keep `cancelRefinement(): void` as the synchronous *request* entry point, not proof. Add `retire(): Promise<RetirementOutcome>` to `LiveRuntime`. `dispose(): void` starts/caches that same retirement; it does not release permits or send zero on its own. This preserves unmount/pagehide callers. Admission waits are bounded by the retiring owner's deadline, abort, queue capacity, or an immediate busy error if the current live owner has no planned release. No wait behind a retained playback lease: return a clear busy error; the UI already releases playback first. No promise can wait forever for the user to release a healthy session.

`serializePcmOperation<T>` continues to bound/serialize its queue but uses the shared copy permit. Runtime `refine/export/restore` join this same lane without recursively calling it. Helpers accept an existing private permit; acquiring twice is forbidden. `restore` acquires canonical first, then copy; no operation holding copy waits for canonical. Metadata operations and cancellation/retirement control always bypass the lane.

Change `pcmToWav` to return a private owned WAV handle rather than a naked Blob: `{ readonly blob: Blob; release(): void }`, with the copy permit held through the handle's lifetime. Use a getter backed by a nullable reference, cleared on release, not a permanent Blob-valued property on a released handle. Only the player uses it in product source. `create()` retains this handle, creates URLs from its Blob, and drops local aliases before ending the invocation. `release()` revokes URLs, clears audio/WAV roots and starts cleanup; if build/create is still pending, the permit stays held until that invocation exits, including stale-result rejection. Update the three focused helper tests for the new handle. An exposed handle's release is only valid after the consumer drops its Blob aliases; this is a product-internal ownership contract, not a cap on arbitrary caller-retained objects.

Normal success also releases a copy permit only after a payload-free completion boundary, not merely an ordinary RPC result. For export, the transient array/digest helper must exit before its returned Blob is published. The one cached main Blob is retained and counted separately; publishing it is not an extra export. Runtime cannot allocate another export when that cache already exists. Restore keeps the identical caller Blob. Preserve UI's one retained PCM session and exact Blob/generation checks; arbitrary callers retaining multiple sessions are outside this bounded product flow. Newly IDB-loaded Blobs remain distinct and are not deduplicated by hash/size.

### State transitions and enforceable allocation sites

Slot states are `empty → owned → retiring → empty`, or `owned/retiring → blocked`. A retiring slot freezes **new admission into both slots**; existing owners may only drain. Blocked is terminal for the current document, including BFCache restoration and React remounts. Queued callers carry only their own abortable admission request and cannot post a Blob/transfer/construct a worker until admitted. Bound each queued admission to 16 s (or the earlier retirement deadline/abort); this is a wait-to-start limit, not a shortened 120 s refinement limit. Reject/retire a newly prepared empty runtime if its subsequent copy admission fails. Permit completion is single-use. A cancellation rejects the user's operation promptly, but does **not** complete its permit. A normal error can carry genuine drain proof; a transport error or crash alone cannot.

Before posting any admitted allocation command, main synchronously records its owner/request/permit. Cancel/dispose synchronously seals it before posting retirement. Workers reject commands beyond that fence and all ordinary results after cancellation. Full-copy authorization is bound to the receiving worker object, owner, kind, request and generation. Workers guard immediately **before** `Recording.copy`, `pcm.arrayBuffer`, export array/Blob construction and resumed post-await canonical append. Move the existing analyze budget check ahead of its allocation; reserve the complete source envelope first. No new large work can be smuggled in by a queued handler whose main promise has already rejected.

Live analysis is the existing bounded small-window path, within the separately carried R reserve; it cannot run concurrently with stopped full-copy work. It must not boot a replacement analysis child while its predecessor's retirement is unproved. `pump`, stop/watchdog continuations and capture callbacks check terminal/retiring state before allocating or scheduling work. `Recording.release()` cannot be undone by a late restore continuation. A capture port is sealed/closed and late queued PCM is rejected without creating canonical/decision copies; drain any already entered capture callback. Preserve the eight-buffer transport bound. For this package, whole retirement of an attached capture requires the **received genuine end boundary**, whose same-port FIFO follows the last PCM and whose worklet sender sets `ended` before producing again. Track this separately from `ended` set by `forceStop`/watchdog. Port close, context close and a watchdog alone cannot certify a drained producer queue. Active-capture teardown without that barrier takes the blocked fallback; adding a new worklet retirement handshake is explicitly deferred. The package's numerical cap proof remains for stopped 300 s retry/Save/play, not a new proof of every capture input rate or UI route.

### What a genuine retirement reply proves

Wire additions: `retire` and `retired` carry the exact `Retirement`; `retired` has no audio payload. Main generates `ownerId` per actual ingestion/verification Worker; ingestion generates a separate child ownerId per analysis Worker. **Do not reuse `Key.generation` for child identity:** current code replaces it with `engineGeneration`. Fence includes that child's key and owner; parent wraps child proof under its own session key. Version 1 here versions this cleanup envelope, not the Rust bridge/schema.

1. Intake seals synchronously on `retire`. Main has stopped posting ordinary messages on that channel; `throughRequestId` names the last command it posted. Child analyze and retire use the same sender/channel FIFO. Already queued handlers through that watermark must be accounted for; a processed control message alone says nothing about their suspended invocations. No further engine worker can be created under a sealed owner.
2. Analysis calls existing `backend.close()` (or `portable.close()` if initialization has no backend yet), catches cleanup failure, and never calls guest exports again. At an Asyncify yield, close resolves the pending task; `call` sees closed, rejects without rewind, and analysis unwinds. Refactor payload handling into a helper that returns metadata only; count the **entire invocation**, including parsed request, input view, catch/finally and event-data aliases. Suppress its canceled result/error. Check sealed state after initialization awaits, before installing backend/sending readiness, and in finally so neither can restore `ready`. Initialization must also settle/drain before certification; close-throw/pending init cannot be relabeled released.
3. A small outer dispatcher attaches a settlement continuation that captures only IDs/state. It schedules the finalizer through a reusable MessageChannel **after** the payload helper and dispatcher invocation have returned, active count is zero, all admitted requests through the watermark were handled, and intake is terminal. No `.then`/waiter/list/error object may retain the payload/event. This extra task is a code-lifetime boundary, not an exit-delay assumption. A successful ordinary analyze gets a matching payload-free `input_released` completion at this boundary before its copy slot can be reused. Ingestion buffers a matching ordinary result but does not resolve its waiter, zero `transferBytes`, or start the next job until `input_released` also arrives. A normal completion leaves intake open for the next admitted command; a retirement finalizer permanently seals it.
4. Ingestion receives the genuine child proof on the registered child Worker, then may terminate that child. The transferred input remains reserved until this proof: sender detachment was movement, never release. A failed send with uncertain detachment poisons admission. After successful send, sender's detached views are not a second payload. Queued transferred inputs are included in the child watermark; a result/error/request mismatch cannot retire them.
5. For whole-runtime retirement, ingestion also waits for entered `prepare/restore/export/refine/stop/pump` helpers to finish; pending Blob reads/digests must settle, and canceled continuations must skip decoding/append/result publication. Reject/resolve local metadata waiters for end/drain/boot/analysis so these helpers can unwind; rejecting them does not discharge a still-running payload helper. Release canonical chunks/ring, resampler, decision arrays, port callbacks, caches and pending job roots. No `forceStop`/pump restart after retirement. Only then does the payload-free finalizer send parent `retired` containing the joined child retirement outcome. A parent cannot certify a child it merely terminated. Ordinary cancellation retires only analysis; it preserves canonical PCM for export/retry until whole retirement is requested.
6. Verification uses the same pattern: seal one-shot intake, let the entered read/digest helper return or reject, drop request/event/bytes/DataView/digest roots, then send one metadata-only finalizer reply with its outcome and retirement identity. Abort rejects Save immediately but keeps the copy permit. Success/error is not trusted from today's unfenced `{ok:true}` response. No second request can start on that worker.

The source audit must show the finalizer cannot capture or rediscover any relevant PCM root and no pending callback can recreate one. This is an application ownership certificate, **not** a native free/GC or OS exit certificate. `active = 0` and a posted string are evidence only after that source obligation is independently reviewed. If it cannot be met for a helper, do not emit proof; take the blocked path.

Stale owner/key/generation/request/watermark/version replies are ignored and do not mutate admission. Matching malformed or contradictory replies poison the owner. An exact duplicate terminal reply is ignored without a second release; an error outcome cannot turn a quarantine into success. Old result/readiness/status messages never satisfy retirement. Route cleanup sideband before normal `worker !== owned`/current-UI-key filtering so a legitimately retiring predecessor can finish, but only through its registered Worker handle. Never clear its cleanup route merely to reject old user results.

### Hard cancellation and finite failure

At the cancel handler: seal admission and send cooperative retirement immediately; cancel UI work without losing its resource obligation. Use a **100 ms cleanup deadline measured from that original handler**, not from each nested retire or repeated click. After successful cleanup, a later independent whole-runtime disposal has its own deadline; it cannot restart an unresolved child's deadline. If genuine drain arrives earlier, terminate the retired worker then. Otherwise invoke existing hard `terminate()` by the deadline, mark the slot/document blocked, reject all queued admissions, and show “Audio cleanup could not be confirmed. Previous results are kept. Reload this page before starting more audio work.” This is a failure deadline, never a sleep or evidence that termination has completed. No ack after the deadline unblocks the document.

Retain original **actual whole-worker CPU cessation ≤250 ms after handler** as a separate acceptance obligation on both cooperative and forced paths. A timer firing or an API returning does not prove it. There is no portable exit Promise: this source-only design cannot guarantee a browser's physical exit latency. The 100 ms policy leaves time for the existing hard stop but is **not** a claim that the remaining 150 ms is enough. If the busy-worker evidence exceeds 250 ms, this candidate fails that original gate. Do not relax it or claim admission safety passes CPU acceptance.

For spontaneous worker error, malformed transport, boot failure, normal operation timeout, or unresolved `arrayBuffer`/digest, start the same cleanup deadline when detected; preserve existing 5 s/120 s/15 s operation limits. The new deadline only bounds cleanup after cancellation/failure. If a native read never resolves, no further read/copy is admitted and UI still has a finite blocked outcome. Pending initialization is handled identically. No timeout, `onerror`, terminate-return, counter zero, UI release, new facade, or cache clear manufactures release. Metadata/JSON results remain usable; audio Save/play/download/refine/new capture are blocked if they would allocate. Already saved recordings are not modified; a reload may discard unsaved in-memory audio, and the message must not promise its recovery.

Fresh facades cannot bypass this by choosing a new generation or sessionId. There is no deadlock: retirement uses no admission slot, canonical acquisition never occurs while holding copy, a healthy occupied slot returns busy rather than waiting indefinitely, and every retiring owner has the same finite deadline. Once blocked, no replacement worker/session is created. Root/browser harness may later observe old exit for diagnosis; that is not a production unlock mechanism.

## Bound and proof obligations

Let P=28,800,000, R=983,040, Q=131,072, E=R+Q=1,114,112, W=14,400,044. Keep one extra R conservatively as in the maximum proof. With one canonical owner, one joined PCM Blob and one copy operation, export/verify/WAV stay within **88,497,240 bytes**; restore's **88,562,720**, including its 65,536-byte scratch, is the larger proposed-path envelope. This is below 100,663,296; the design does not pretend every phase is covered by the old maximum execution. New envelopes require validation.

While old analysis/ingestion retirement is unresolved, new canonical construction, full Blob reads, refinement/export copies, WAV construction and verification are inadmissible. Old admitted native reads remain reserved from invocation through helper return. Therefore pending-read allocation time no longer matters: no new read is requested across the unsafe boundary. The forced fallback retains old reservations and admits nothing further; it never turns the old four-P uncertainty into free space. Repeated failed clicks allocate no new worker or payload.

WASM linear memory and saved stack stay **separate**, maximum 134,217,728 per module, saved stack counted once inside linear memory. Do not move the JS analysis input into that budget, change the binary, or infer old WASM/native backing reclamation from a JS retirement ack. Generated facade keeps module-level WASM references until realm destruction. The protocol proves JS/PCM-root retirement; it does **not** introduce an aggregate across-generations 128 MiB physical-memory guarantee. Report old/new WASM realm overlap separately and retain the original module limit/native-GC limitation. An aggregate application-owned WASM requirement would need an additional design/source change; it cannot be silently claimed here.

Verification abort/timeout admission **is included**, because its existing full read fits the same copy slot and drain primitive. Its real abort/timeout behavior remains unexecuted. Keep atomic save semantics: no IDB write following a rejected verification. Broader capture-rate maxima, arbitrary multi-session API callers, browser-native Blob/WebCrypto/IDB backing reclamation and musical/performance acceptance remain outside this package.

## Focused red/green controls and later acceptance

Use deterministic transport controls only for protocol/lifetime assertions. They do not establish a busy Rust phase or CPU stop. Each red control must demonstrably fail against the present early-release behavior before treating its green result as meaningful.

1. **Withhold a genuine reply:** run the real retire/drain finalizer in an owned worker; have transport intercept its actual metadata-only `retired` output, without fabricating it. Immediately request fresh-runtime restore with the same maximum Blob. Before deadline assert zero successor ingestion constructors, zero `Blob.arrayBuffer` requests, zero `Recording.copy`/canonical append/WAV/verification allocations and no acquired successor permit. Deliver the retained genuine reply before deadline: exactly one successor is admitted, only after both input and canonical proof. A separate withheld-through-deadline control must end blocked with zero successors, even after a late genuine reply. Run the same hold at the child input-release boundary before first export when PCM was not previously cached.
2. **Drain, not receipt:** hold an admitted payload helper at a controlled read/yield Promise; let retire be processed. Assert no reply until that helper and its outer event/request scope exit. Resolve it, ensure canceled continuation cannot append/copy/publish, then observe the actual finalizer. Test a queued transferred analyze preceding retire and a late queued request after seal. Join the real transfer and detachment tuple. This is protocol proof only.
3. **Fence controls:** stale session, generation, owner, request, watermark, protocol version, unrelated Worker and ordinary result/ready/status cannot release. Exact duplicate cannot admit twice. Matching malformed/contradictory proof blocks. Normal analysis/verification error with real drainage may release its slot while returning error; error-only, thrown close, transport failure, uncertain postMessage transfer and lost reply cannot. Cancellation twice shares the first deadline/fence. Wrong child proof cannot retire its parent.
4. **Positive lifetime controls:** ordinary refine/export/restore complete and release; cached export remains the identical Blob; prepared WAV keeps its permit until release; release during pending WAV build waits for stale helper exit; no nested getPcm→WAV deadlock. Fresh facade generation, remount and BFCache cannot reset quarantine. Aborted queued waiters do not post/allocate. Queue capacity stays eight. Capture without the genuine end barrier cannot retire successfully. Successful/invalid-hash verification drains and returns correct outcome; abort/15 s timeout keeps admission until genuine finalizer or blocks within cleanup deadline. No subsequent IDB write on rejected Save.
5. **One later, separately granted busy-worker cancellation + immediate retry case:** exact candidate/build bindings first. Use actual 300 s source-bounded PCM, begin real Rust computation, establish OS worker identity/CPU activity and the handler epoch, cancel, request retry immediately with the same Blob. No fake backend, inserted compute delay or changed yields. Record real child/parent proof tuples, actual allocation admission, sender detachment and cross-realm Blob joins. Show old payload roots ended before new full-read invocation and conservative simultaneous bound ≤96 MiB. Observe actual whole-worker CPU cessation by 250 ms independently; cleanup ack alone cannot pass it. Report functional, memory, CPU and phase separately. If forced fallback occurs, the correct result is bounded refusal to retry, not a successful retry PASS. Force-path CPU acceptance requires a real observation too; a withheld transport message alone cannot supply it.

Stop on a missing ownership join, forbidden pre-proof copy, late actual CPU stop, unsupported drain path, or deadline exhaustion. Preserve the first failure; no broad repeat campaign. Review source/helper captures and the focused controls before authorizing that real-worker case. Existing exact-byte/safety scopes are consumed, not reopened by this design.

## Handoff

The unavoidable tradeoff is **retry availability**: an unresponsive owner can be stopped while its memory release remains uncertified. The safe outcome is blocked audio work until a genuine new document replaces this one. Active-capture teardown without the existing end barrier also fails closed in this limited package. Without this tradeoff, browser exit notification, or a substantially different ownership scheme, a guaranteed immediate retry cannot be justified from these APIs.

Retained WPE **557.8 ms**, Node **557.2169716 ms**, and repaired diagnostic **537.39608 ms** failures remain FAIL; musical acceptance remains NO-GO. No adoption, performance repair, Firefox diagnosis or browser campaign is claimed or scheduled.

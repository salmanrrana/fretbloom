## Dual backend versus portable whole-call Asyncify

Dual JSPI/Asyncify retains a smaller587,478B primary WASM and an already exercised modern-browser path, but requires two ABIs/generated sets, feature selection, error/lifetime paths and separate acceptance. Portable-only could remove the primary selection/adapter path and reduce the validation surface while preserving whole-call recognition; it still needs a pinned Binaryen/numeric-handle transform, safe saved stack and correct async ownership. It is not a return to independent/chunked analysis windows. [Compatibility design](rust-cancel-compatibility.md#L7).

Current portable feasibility: larger1,472,920B WASM, two warmups+five samples in one block, simple valid300s call, limited real-worker Firefox/Chromium cancellation. It is neither complete product integration nor three-block/browser-floor acceptance. The observed2832B saved-stack high-water and1MiB allocation **do not prove pre-write bounds safety**; the prepared guard has not been validated on the full artifact. The prepared dual-source freeze still has the old facade. [Feasibility limits](rust-cancel-compatibility.md#L33), [browser limits](rust-cancel-compatibility.md#L55), [prepared guard blocker](rust-cancel-portable-implementation.md#L93).

**Recommendation:** prefer portable-only *if* a guard-safe whole-call backend independently satisfies all unchanged product and explicitly agreed comparative gates across the supported browser floor, exact outputs/errors, busy CPU-stop≤250ms, compute/event-delay/backlog, valid300s refine, pre/post gaps, re-entry/traps, retained PCM/request-identity/retry, complete owned-memory/overlap accounting and five-cycle cleanup, with reproducible packaging. Browser/native memory and load/download cost matter alongside linear memory; count its saved stack within linear memory once. Natural old-Chromium/WebKit evidence and support scope must be settled by their owners. Node feasibility alone cannot decide this. Retain dual only if measured product/coverage/resource evidence demonstrates a useful advantage; the present Node anomaly does not establish such an advantage for either choice. No adoption decision is made here.

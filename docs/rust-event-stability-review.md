## What production actually does

Paths in this section are relative to `crates/fretbloom-analysis/src/` unless stated otherwise.

1. **Physical hypotheses and support — `lib.rs::analyze`, `polyphony.rs::fit`, `voice_evidence.rs`.** Each 480-sample/20 ms cell gets RMS; below 0.00004 is absolute silence, resetting temporal evidence and uncertainty counters. A centered 4096-sample spectrum supplies measured fundamentals and a sparse fit of at most six voices. Admission uses independent residual peaks or temporal shared-partial evidence, not chord names. Temporal evidence keeps 24 hops and needs six confirmations for shared ownership; this is distinct from segmentation's three hops. Local 1024-sample measurements and the phase-fixed predictor support this decision. Tonality additionally requires cell RMS relative to the centered window, guarding quiet gaps from neighboring loud energy.
2. **Current presence — `current_support`.** Candidate-specific projections inspect fundamental and up to four partials, disjoint halves spanning 40–120 ms in total and a central 20 ms cell. Missing measured fundamental or missing central fundamental presence yields `Absent`; coherence/amplitude checks yield `Confirmed` or `Uncertain`. These are algorithmic classifications, not infallible source truth. `lib.rs` promotes at most two uncertain hops for a previously retained pitch. It filters current fit and bass by this result and records an absence bit for tested fit/previous/bass pitches. A previously present pitch that disappears from the fit is tested for absence but is **not reinserted** merely because current support confirms it. Raw uncertainty versus the promoted result is not retained in `Frame`.
3. **Mono decision — `lib.rs`.** YIN must explain >96% of observed partial energy, have support >0.86, an observed fundamental and current support, with additional independence/tight-fit vetoes. Passing replaces `fit.notes` with the singleton and sets bass. `Frame.mono` is the resulting decision, not an onset detector. A failed YIN condition can change route despite a continuously present fitted pitch. A faulty mono override could instead remove a real voice; segment merging cannot recover it.
4. **Smoothing and physical confirmation — `segments.rs::finish`.** Clone the frames, use a three-frame MIDI majority on interior nonsilent cells, veto filling a pitch with its `absent` bit, and retain mono only if the original center had matching mono and the smoothed set is singleton. Then delete contiguous physical pitch runs shorter than three hops, independently of route. Thus routing no longer restarts physical confirmation. Smoothing may still alter genuine brief attacks/transients; there is no pitch-local onset field to protect them. Silence cannot itself be filled, but nonsilent neighboring cells can still be modified.
5. **Note events.** Iterate separately over mono/poly and each MIDI. Every routed presence run becomes an event at 20 ms edges, with averaged cents/support. Auto uses mono where available, otherwise poly; explicit mono refuses non-mono cells rather than outputting their lowest pitch, and explicit poly uses the note set. Route changes split runs even without release. `route_changes_do_not_erase_a_continuously_supported_pitch` explicitly expects three mono plus three poly spans for twelve continuously supported cells. No same-pitch attack can split an otherwise continuous run. `MAX_NOTES=4000` is enforced separately on each stream during append, before harmony construction. Output sorting happens afterward.
6. **Bass and harmony.** Bass is refit on the 8192-sample spectrum every four hops or when absent, with current support filtering between refits. The segmentation bass filter requires five matching nonsilent estimates in the five-frame neighborhood; at input edges that is impossible, and real changes create null transition regions. Harmony chooses silence, unpitched, insufficient-evidence unknown, or `chords::infer` on the smoothed/confirmed notes. Chord inference keeps missing defining tones and ambiguity explicit. Adjacent harmony merges on `same_kind` plus exact bass MIDI: chords compare complete chord identity (including bass PC), unknowns compare reason and only their FIRST alternative. Merged payload remains the first event's payload. Consequently later alternative changes can already be lost; blindly broadening this merge would worsen honesty.
7. **Harmony cap and demotion.** The 3,000 cap is checked after each initial append. Only later are chord runs shorter than 60 ms demoted to unknown with alternatives. Confirmation groups constant root/quality across bass boundaries, correctly avoiding demotion merely because bass changes. There is no final coalescing pass after demotion. This ordering can reject an intermediate representation before a canonical final one exists. It does not prove that demotion/coalescing would bring palm mute below 3,000; different alternatives and genuine bass transitions still require distinct events.
8. **Other bounds and live reconstruction.** Native input is capped at 600 s; the final result also has a roughly 1 MiB envelope allowance. Features use four-hop/80 ms groups and remain a separate contract. In `src/audio/live/rollingTimeline.ts`, results are clipped to supported regions, split into cells, then adjacent same-MIDI spans in each stream are merged without remembering whether the original input contained a reattack. This would erase adjacent same-pitch events produced by a repaired core. Live harmony uses a richer ordered-alternative identity than Rust. Live caps are enforced after merging. Missing coverage stays unknown. Rolling calls are stateless, with 2.56 s windows, .64 s warmup and .32 s future reserve; reconstruction must not invent cross-call physical evidence.

**Causal limit:** route splitting, loss of pre-promotion evidence, absence of attack identity, early harmony cap and live reattack merging are source-supported mechanisms. Which mechanisms dominate each failed full input is unproved here. The independent production-path traces must separate pre-fit loss, physical-support loss, median/confirmation loss, routing splits, real attack splits, bass changes and alternative changes. A generic spectral probe using different preceding fits is not an exact production trace.

## Objections, limits and release

The smallest safe repair is not “merge near notes.” It is to preserve measured attack/release evidence, reconstruct physical intervals, project honest routes, finalize harmony, and prevent the live merger from erasing those boundaries. Some of these changes may increase event counts by restoring genuine reattacks or alternatives. That is an acceptable diagnostic outcome, not a reason to delete them.

The existing support classifier can mistake model inadequacy for absence. Its absence decisions must remain barriers until a separately demonstrated physical-evidence correction justifies changing them; removing the barrier is not that correction. Shared-harmonic ownership, C6/madd11 omissions, legacy real extras and late shared-sustain truth failures remain open. No event algorithm recovers a voice never admitted, proves source count for signal-identical audio, or uniquely selects a chord name from acoustically equivalent sets.

If faithful output exceeds the frozen caps, or acoustic evidence cannot distinguish sustain from reattack within existing support/latency, retain failure and state the exact representation/evidence conflict. No increased caps, truncation, subsampling, discarded transients, false silence/unknown, relaxed parsers, favorable crops, modified labels/thresholds, or new model dependency is authorized by this review.

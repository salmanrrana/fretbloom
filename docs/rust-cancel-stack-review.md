For example, add the following to the existing fixture while retaining its four canonical access classes:

```wat
  (i32.const 123))
```

The inner metadata load is accepted, the outer saved-stack store receives no guard, and the nonzero-class check at `:147` still succeeds. Similarly, assigning that load to a fresh local avoids both the cursor-local discovery at `:99` and the escape check at `:122`. This conclusion follows by following the predicates; it is **not a test pass**. Aggregate counts would change in these examples, so a correct independently established future count pin would reject drift. They still disprove the helper's unconditional “unknown cursor use is a generation error” claim. The current null counts supply no independent coverage evidence.

### R2 — High: traps outside controller.call can re-enter the allocator during cleanup

**Static ownership defect.** `S/scripts/wasm-asyncify-runtime.mjs:53–55` marks failure only for exceptions inside `call()`. Its `close()` calls the guest allocator when `!busy && !failed` (`:73–74`). Input malloc/realloc and result freeing occur outside that catch. `S/scripts/wasm-portable-adapter.mjs:24` marks the facade failed for a non-string error, but does not mark the controller failed; `:46–50` then closes it without carrying the facade's failed state. The worker catch invokes backend close (`S/src/audio/live/analysis.worker.ts:174–178`). Consequently, a WASM trap during input allocation or result free can be followed by a second guest allocator call to free the saved stack. This contradicts the discard-after-trap ownership rule.

Initialization has an earlier path: adapter `:39` invokes generated `engine_info_json()`, then `:41` closes the controller on error. The retained source-only generated facade, `target/cancel-portable-builder/preparation/adapter-source/fretbloom_wasm.js:44–54`, always executes `__wbindgen_free(deferred1_0, deferred1_1, 1)` in the info getter's finally, even if `wasm.engine_info_json()` trapped before the tuple existed. The controller also remains unpoisoned in this path. The preparation source exercise contains no WASM and did not validate this behavior at runtime.

**Fix owner:** follow-up runtime/adapter builder. Carry discard state across **all** guest entry points, including initialization, allocation, info and output cleanup, and skip output free when no completed result exists. The simplest worker-lifetime option is to make controller close dispose only the channel and forbid future calls, leaving the one fixed stack allocation to whole-instance/worker disposal. If clean-close guest freeing is retained, it must be reachable only from an explicitly known-clean state; facade failure must not silently select that path. A trap during cleanup must not cause further guest entry.

**Required tests, not run:** instrumented stub exports/call ledger covering traps at PCM malloc, options realloc, info getter, raw analysis, state/control calls and output free. Assert **zero guest calls after the first trap**, including close and repeated close. Also cover rejected/nonzero yield, close while suspended, initialization close, ordinary string errors, and success after ordinary errors. Real generated-instance tests must follow the source controls; trap cases use fresh disposable instances and never free via a trapped instance.

## What is sound, and what remains conditional

For a **classified** access, the inserted check is a suitable unsigned pre-access check. Let B/E be fixed begin/end, A the evaluated i32 address, O its constant memory offset and W the width. `size()` computes span S = O+W using safe JS integer arithmetic and refuses unsupported/overflowing offsets (`wasm-asyncify-bounds.mjs:59–67`). The WASM helper checks B is configured, A>=B, A<=E and S<=E-A (`:169–175`). Although the nested `i32.or` operations evaluate eagerly, all operands are pure integer operations. A wrapped E-A when A>E cannot undo the separate A>E rejection. For the accepted host interval, successful checks imply the entire effective access lies in [B,E), without computing a wrapping A+S. End-exclusive handling and unaligned scalar accesses are correct; a span-positive access at E traps.

The setter validates nonzero begin, begin<=end and end<=actual memory length using i64 page arithmetic (`:161–168`). Host allocation is `stackBytes+8`, aligned to 8, with begin=pointer+8 and end=begin+stackBytes (`wasm-asyncify-runtime.mjs:5–13`). Under the pinned 128 MiB maximum, these JS integers do not wrap. An abstract 4 GiB host-memory case would need an explicit end<=u32 check; it is outside this pinned module. Neither the guard nor the allocator check proves Rust's allocation semantics independently; disjoint ordinary guest allocations and private host control remain premises.

Checks surround the original address expression without duplicating it (`bounds:135`). Native folded WAT evaluates the address/check before a store's value, then performs the store; the original address subtree and scalar offset/alignment remain. Pinned saved-store values are local-get/tuple-extract expressions (`B:1668–1683`, `:1696–1702`), so no new normal-case value side effects were found. On overflow it is intentional that the new trap can occur before a value expression. Insertions preserve original substrings; that alone does not prove valid assembled WAT or correct metadata coverage. The final `lastIndexOf(')')` (`bounds:178`) also assumes pinned wasm-dis output ends with the module close; trailing comment parentheses or flat/mixed syntax need refusal/canonicalization if accepted inputs expand.

Metadata header reads/writes are **not** wrapped. Their safety follows only if the data pointer remains exactly the private eight-byte host allocation and the approved offsets are 0 and 4. Cursor arithmetic is modular i32 arithmetic and is not checked when the header changes. Individual guarded accesses prevent an ensuing out-of-allocation stack access; they do not on their own establish correct frame accounting, detect every wrapped cursor update, or make the header/control assumptions true. Rewind's decrement precedes its load (`B:1454–1465`, `:1612–1615`), which is why lower-bound checks and explicit underflow controls are essential.

The four emission families in this pinned writer are call-index pop (`B:1454`), local load (`B:1598`), local save (`B:1651`) and call-index push (`B:1693`). Numeric scalar locals from these sites fit the helper's intended forms. `getByteSize` does not support reference locals (`B:1706–1712`); the metadata-to-numeric bindgen step addresses that separate limitation. Future SIMD/other access forms must fail closed, not disappear from the inventory. The present raw/tool pins and no-SIMD policy narrow this concern, but there is no completed actual-module inventory to certify here.

Indirect-call handling is conservative: the command uses only the host poll import and asserts (`wasm-portable-build:41`), with no ignore-indirect or removelist; `B:1737–1739` defaults to indirect calls changing state. The postprocessor walks all defined functions, not a hand-picked direct-call graph. This is the right policy for the Rust cancellation callback. Assembled import/control/table audits and callback-bearing execution are still missing.

The guarded facade does not export raw memory, allocators, sync init or an instance (`wasm-portable-adapter:18–53`); initialization returns void, caches info before analysis, and ready checks precede allocations. Worker selection depends on both JSPI APIs (`analysis.worker:57–80`) and the worker's busy guard precedes analysis allocation (`:113–131`). Partial unwind tuples are discarded until state zero (`asyncify-runtime:42–49`). Close while suspended closes/resolves the channel and avoids freeing the live stack (`:66–74`), then call rejects on closed before rewind (`:50–51`). These are sensible ownership choices, subject to R2 and unexecuted lifecycle controls. Failed/discarded workers must actually be terminated by their owner; this source review did not certify facade-level cancellation, CPU disappearance or old/new-worker overlap.

`memoryBytes()` reports the whole linear memory (`wasm-portable-adapter:44`), including stack/header and allocator/page overhead; `savedStackBytes()` exposes only the owned allocation size. Add no second stack charge. The module's 128 MiB max (`wasm-verify:15`) caps that single memory; it does not establish JS, browser-native or overlapping-worker limits. Worker memory checks are post-analysis (`analysis.worker:134–142`), not an independent memory ownership measurement. The earlier 2,832-byte observed high-water and 1 MiB capacity prove neither universal stack safety nor full product memory acceptance.

## Smaller proof surface: a narrow pinned writer patch

I recommend the builder first compare a **small, explicitly pinned Binaryen 125 patch** against extending this postprocessor. Add fixed private lower/upper/header configuration, then generate checks at the four emission sites above. Push checks 4 bytes before the call-index store; pop validates at least 4 bytes before decrement/load. Local save computes its checked total once and verifies available span before any store; local load validates that total before decrement and any load. Sum totals/offsets without overflow in the tool and preserve the existing ordering, local types, conservative indirect analysis and ordinary memory. Validate the header/control contract at configuration/start/rewind. Keep terminal assertions as additional diagnostics.

This is a concrete simplification: the code writer already knows each saved type, byte width, offset and total; it does not need to rediscover provenance through WAT syntax, identifiers and aliases, and it removes two text/binary round trips plus the large parser. Frame preflight is sufficient only after proving every emitted load/store lies in the checked frame; use actual emission-site evidence and adversarial typed/tuple fixtures, not a single canary run. No multi-memory, shared memory or browser-floor change is proposed.

The cost is a custom tool build: official prebuilt wasm-opt hashes can no longer authenticate the patched binary. It needs an immutable upstream source hash, patch hash, build recipe/toolchain identities, resulting executable hashes, license and reviewed output identities, then inclusion in the normal source/tool manifest. Reproducibility is an unexecuted gate, not an assumption. If obtaining that tool closure costs more than closing R1/R4 for this exact pinned output, retaining a hardened, independently reconciled postprocessor is acceptable. Merely replacing the 181-line helper for appearance is not the reason; reducing the safety proof from reconstructed syntax to four typed emission sites is.
